# 路线图

## 当前状态

M1–M4 的核心代码路径已经落地，macOS 发布包构建、签名和启动通过。Linux/Windows 真实终端与监控、多标签、SFTP 小文件传输、目录树、四区 UI、右键菜单、默认私钥和敏感字段脱敏已验收。缓存文件的普通保存及 VSCode 式原子改名保存均已验证自动回传一致。

近期修复的主要路径已验收：关闭标签立即释放 UI 并异步清理后端会话；自定义连接通过应用内确认弹窗永久删除；OpenSSH 连接仅从应用隐藏且不改用户配置；前后端日志查看、30 秒 SSH keepalive、暗色自定义下拉、网络与资源图表、系统信息弹窗、缓存下载进度锁和桌面 sidecar 本地网络权限/签名问题。日志三天保留策略已实现，时间跨度清理仍需后续观察。

以下验收仍需补做：vim/htop 长时间兼容性与性能、100MB 文件传输、Finder 实际拖入手势、真实断网后的自动重连、未知主机指纹确认完整交互、原生应用选择器实际选择、桌面 Cmd+V 实际粘贴、真实密码登录，以及日志经过三天后的自动清理。Windows `cmd.exe` 不支持 Bash/Zsh 的 `cd` 路径联动。

## M1 — 骨架跑通

- Tauri/WebView 加载前端，并管理本地 Go sidecar 生命周期
- 后端：token/Origin 鉴权、HTTP+WS 服务启动
- 后端：从 M1 开始校验 `known_hosts`；未知主机明确确认，指纹变化拒绝连接
- 后端：SSH Agent / 公钥建立 SSH 会话，WS 双向桥接字节流
- 前端：xterm.js 页面，输入输出可用
- 验收：登录 `socat-248`（Windows）与 `campanula-248`（Linux），执行 `ver` / `echo` 正常显示

## M2 — 日常可用

- profiles REST + `~/.ssh/config` 导入，使用 `ssh -G` 获取生效配置
- resize 同步、bracketed paste
- SFTP 列表 / 流式上传 / 流式下载
- 验收：vim 编辑远程文件、htop 布局正常、SFTP 传一个 100MB 文件且内存占用不随文件大小线性增长

## M3 — 多标签与断线体验

- 多标签页，每个标签页一条独立 SSH 会话，切换标签不销毁 xterm 实例
- SSH keepalive、远程断线检测、自动及手动重连
- 断线和重连期间保留当前标签页已经渲染的终端内容，禁止自动清空
- 断开期间禁用终端输入且不缓存按键；重连成功后，新 shell 输出追加到原终端
- SFTP 拖拽上传、进度显示
- 终端内搜索
- 验收：
  - 同一主机打开两个标签页，两个 shell 独立执行命令，输出不串流
  - 远程断网后，原终端内容仍在且状态灯正确；恢复网络后建立新 shell，旧内容继续保留
  - 拖拽上传有明确进度，中断的传输显示失败，不伪装成续传成功

## M4 — 四区工作台与缓存编辑

- 左上资源监控、右上 Shell、左下远程目录树、右下当前目录文件，文件区常驻
- 绝对路径解析与复制，目录树从 `/` 按需展开
- CPU/内存/交换/进程/网络/延迟/磁盘监控，进程 CPU 和内存可升降序排序
- 磁盘显示路径、已用/总大小和比例条形图
- 文件双击下载到本地缓存并调用系统默认编辑器，保存后自动回传原远程路径
- 验收：VSCode 修改并保存缓存文件后，远程内容一致；目录树与右侧路径联动；监控排序和图表正常
